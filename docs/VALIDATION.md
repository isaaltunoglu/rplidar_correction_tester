## Reproduce the completed browser checks without a sensor

```bash
python3 -m pip install playwright==1.61.0
python3 -m playwright install chromium
python3 tests/browser_smoke.py
```

On Linux CI, Playwright can install OS dependencies using `python3 -m playwright install --with-deps chromium`. The workflow already includes this command. Screenshots and exported sample files appear in `artifacts/browser/`. Captures are taken from the document top after fonts, page motion and notifications settle. The 1,000 mm synthetic target produced an approximately 999.4 mm mean in the captured run. These are simulation and software-behavior evidence, not hardware measurements.

## Evidence boundaries

Host receipt timestamps are not synchronized optical measurement timestamps. SSE delivers the latest frame and can omit revolutions; target hit rate is conditional on received scans. Default filters, the view-radius slider and the mode's nominal range are not verified sensor limits. Simulation can validate software behavior while proving nothing about actual sensor accuracy, laser safety, power, thermal performance or suitability for a robot's protective function.

## Follow-up after access was granted

The earlier socket/Chrome restriction no longer applies. Browser execution exposed and led to fixes for a source-change acknowledgement race (a valid newly received scan could be cleared), a misleading other-client notification during a local replay exit, plot/readout label overlap and a cramped mobile toolbar. Paused/stale/replay states now use explicit copy. A DOM regression test forces the SSE-before-HTTP-reply ordering. The browser harness also respects the application CSP and settles scroll, focus, motion and notifications before capturing fixed navigation. The security policy was not weakened.

`artifacts/browser/checks.json` records the checked flows, viewports, lack of page errors and explicit `physical_sensor_verified: false`. Screenshot files and generated trial/recording/report evidence are under the same directory. GitHub CI has been prepared but was not run remotely.

## Beginner workflow revision

The later user feedback requested a UI understandable without LiDAR, statistics or JSON knowledge. The expanded Chrome check now covers all six question-based preparation guides, hidden advanced controls by default, centimetre-to-millimetre conversion, explicit synthetic target preparation, a plain-language report, direct playback without downloading, inline replay/rewind, and recovery after choosing the wrong JSON kind. The additional recording-player capture brings the matrix to 13 desktop/mobile images. These remain synthetic software evidence; no novice participant study or physical sensor test is claimed.

A bounded mechanical pass found low contrast in the selected-preset subtitle and the dark plot button's hover style; both were corrected. Small plot/source labels were increased to at least 12 CSS pixels. Existing context-specific color and size catalogs need to follow the deliberate new beginner hierarchy; they do not imply a new hardware result.
